## 1. Фізична Розмітка Пам'яті (`RingBuffer[T]`)

Для запобігання ефекту **False Sharing** при високій конкуренції між ядрами CPU, атомарні змінні (`head`, `tail`, `state`) ізольовані у різних 64-байтних кеш-лініях за допомогою вирівнюючих масивів-падінгів (`_[56]byte`).

| Зсув в пам'яті | Поле структури | Розмір | Призначення та Cache Line |
| :--- | :--- | :--- | :--- |
| `0x00 .. 0x37` | `_ [56]byte` | 56 B | Ізоляція від попередніх даних у купі |
| `0x38 .. 0x3F` | `head atomic.Uint64` | 8 B | **Cache Line 1 (64 B):** Позиція читання (Consumer) |
| `0x40 .. 0x77` | `_ [56]byte` | 56 B | Ізоляція між `head` та `tail` |
| `0x78 .. 0x7F` | `tail atomic.Uint64` | 8 B | **Cache Line 2 (64 B):** Позиція запису (Producer) |
| `0x80 .. 0xB7` | `_ [56]byte` | 56 B | Ізоляція конфігурації |
| `0xB8 .. 0xBF` | `mask uint64` | 8 B | **Cache Line 3 (64 B):** Маска ємності (`capacity - 1`) |
| `0xC0 .. 0xC3` | `state atomic.Uint32`| 4 B | Атомарний стан (Closed / Draining) |
| `0xC4 .. 0xF3` | `_ [48]byte` | 48 B | Доповнення лінії кешу (загалом 64 B) |
| `0xF8 .. 0x10F`| `slots []Slot[T]` | 24 B | **Cache Line 4:** Дескриптор слайсу (Pointer, Len, Cap) |

## 2. Покроковий Виконавчий Код Конструктора

Нижче наведено покроковий розрахунок виконання конструктора при створенні буфера із запитаною ємністю $N = 5$ та типом даних $T = \text{int}$ (`NewRingBuffer[int](5)`):

```go
func NewRingBuffer[T any](capacity uint64) (*RingBuffer[T], error) {
    // Вхідні дані: capacity = 5

    // Крок 1: Валідація вхідних значень
    if 5 == 0 { return nil, ErrInvalidCapacity } // false

    if 5 > maxCapacity { return nil, ErrCapacityTooLarge } // false (5 <= 2^62)

    // Крок 2: Перевірка, чи є 5 степенем двійки (2^n)
    // (5 & (5 - 1)) => (5 & 4) => (00000101_2 & 00000100_2) = 00000100_2 (4 != 0)
    if (5 & (5 - 1)) != 0 {
        // Крок 3: Округлення 5 вгору до найближчого степеня двійки
        // bits.Len64(5 - 1) = bits.Len64(4) = 3 (число 4 = "100"_2 має довжину 3 біти)
        // 1 << 3 = 8 (00001000_2)
        capacity = 1 << uint64(bits.Len64(5-1)) // capacity тепер дорівнює 8
    }

    // Крок 4: Обчислення побітової маски
    // mask = 8 - 1 = 7 (00000111_2)
    mask := capacity - 1

    // Крок 5: Виділення пам'яті під 8 слотів у купі
    // 8 слотів * 16 байтів/слот = 128 байтів у купі
    slots := make([]Slot[int], 8)

    // Крок 6: Ініціалізація початкових секвенсорів
    // Цикл i від 0 до 7:
    // slots[0].sequence = 0, slots[1].sequence = 1, ..., slots[7].sequence = 7
    for i := uint64(0); i < 8; i++ {
        slots[i].sequence.Store(i)
    }

    return &RingBuffer[int]{
        mask:  7,
        slots: slots,
    }, nil
}
```

## 3. Q&A: Чому mask = 7 працює ідеально для будь-якого індексу?

### Питання:
Чому побітова операція `index & mask` повертає точний індекс у масиві для будь-якого числового курсора (наприклад, $13$), і чому це швидше за ділення за модулем?

### Відповідь:
Коли ємність $N$ обмежена степенем двійки ($N = 2^k$), її маска $M = N - 1$ складається виключно з $k$ молодших одиничних бітів ($1\text{s}$). Застосування побітового AND з такою маскою "відсікає" всі старші біти ($\ge 2^k$) у будь-якому числі, залишаючи тільки молодші $k$ бітів. Математично це строго еквівалентно залишку від ділення $X \pmod{2^k}$, але виконується за 1 такт процесора (інструкція AND) замість 10–30 тактів, необхідних для цілочисельного ділення (інструкція DIV).

### Практичний приклад: Запис елемента №13 (tail = 13) у буфер ємністю N = 8:

* **Ділення за модулем (повільно):**
  `13 % 8 = 5` (або $13 \pmod 8 = 5$)

* **Побітове AND з маскою M = 7 (надшвидко):**
  `13 & 7 = 5`

```text
  13 : 0000 1101 (двійкова форма)
&  7 : 0000 0111 (маска capacity - 1)
----------------
   5 : 0000 0101 (результат: індекс у масиві)
```
Операція миттєво відображає $13 \to 5$ на апаратному рівні процесора за 1 такт CPU.
